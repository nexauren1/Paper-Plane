# Paper Plane — privacy and AI processing notice draft

This is an implementation note for the privacy policy, not a substitute for legal review.

## What happens to a letter

1. The sender writes plain text. Paper Plane accepts a maximum of 200 characters.
2. The authenticated app sends the letter to the Paper Plane Cloudflare Worker over HTTPS.
3. The Worker checks the Firebase ID token, daily-send limit, duplicate/rate checks, recipient restrictions, and moderation result.
4. The letter is saved in Cloudflare D1 only after the application rules and safety checks have run.
5. Random letters are matched only to a user in the same age group derived from the sender's self-declared date of birth. This is a cohort-separation safeguard, not proof of identity or age. If no eligible user exists, the letter remains queued.
6. A delivered unread letter is scheduled to expire after 24 hours. When opened, its expiry is changed to 48 hours from opening. These values are application rules and should be reviewed before launch.

## AI processing — internal, not a user-facing assistant

Paper Plane sends message text to Cloudflare Workers AI for translation:
- an incoming airplane is translated into the recipient's saved preferred language when the recipient opens the letter;
- a private Chat or Chama message is translated when the recipient taps Translate.

The Worker uses Cloudflare Workers AI model `@cf/meta/llama-guard-3-8b` as a first-pass safety classifier for airplanes and public replies. Content flagged as unsafe is kept out of public view and placed in the Admin human-review queue. Private Chat messages that are not classified SAFE are rejected before storage. If the model is unavailable or produces an invalid result, new submissions fail closed. This classifier can make mistakes and does not replace trained human moderation or a staffed escalation process.

The translation model is Meta M2M100 1.2B (`@cf/meta/m2m100-1.2b`) running through Cloudflare Workers AI. Message text is sent to Cloudflare for inference when an airplane is opened or a chat translation is requested. The original message remains unchanged; translated text is cached in Cloudflare D1 for reuse. A recipient can view the original message. The translation model is not used to write messages for users, impersonate pilots, or moderate messages.

The currently selected Cloudflare AI models list zero-data-retention availability in Cloudflare's model catalogue. This does not mean Paper Plane itself stores no messages: letters are stored in D1 to provide the service, and the policy must explain the application's own storage, access, deletion, and expiry rules.

## Data categories in the current schema

- Firebase UID: internal account identifier; never displayed as the pilot's public name.
- Pilot code and fictional pilot name.
- Self-declared date of birth is used transiently by the Worker; D1 retains only the birth year, derived age group, and declaration timestamp, not the full date.
- Preferred language and optional country code. Country display is opt-in; no precise GPS location is collected by this schema.
- Original letter/chat body, source-language tag, delivery state, timestamps, and cached translations.
- FCM device token, only after a pilot opts into notifications.
- Reports, blocks, public likes, and public replies.

Push notifications use generic text and do not include the letter body.

## Before release, the public privacy policy must state

- that message text is processed by Cloudflare Workers AI for translation, including automatic incoming-airplane translation and translation requested inside Chat;
- where the app stores letters, for how long, and how expiration differs before and after opening;
- how the sender, recipient, moderators, and service providers can access content;
- how a user can report, block, export, and request deletion of an account and its content;
- the legal basis, transfer locations, and contact channel for privacy requests;
- how FCM tokens are stored and how notification permission can be withdrawn;
- how moderation reports and safety records are retained after a letter expires;
- that automated text screening uses Llama Guard 3 8B, that flagged public content is held for human review, and that automated screening cannot guarantee detection of every harmful message.

Do not launch publicly until account deletion and export have been exercised end-to-end, report handling and retention schedules are tested, staffed human review is operating, and the self-declared age-group safeguards and launch-country legal obligations have been reviewed.

## Account access, export and deletion

The account screen provides a JSON export of the profile data, sent and received airplanes, public replies, friendships, conversations, chat messages, reports filed and support tickets. The export is generated by the authenticated Worker endpoint and displayed to the user for copying.

The account deletion flow requires recent reauthentication. The Worker removes the account's Paper Plane profile and associated content, relationships, conversations, tickets, reports and device registrations. It retains a one-way SHA-256 hash of the Firebase UID and deletion timestamp to prevent that same identity from silently creating a new Paper Plane account. The mobile app then requests deletion of the Firebase Authentication identity. Users should be told that deletion can take more than one step if the Firebase identity deletion fails after the service data is erased.
